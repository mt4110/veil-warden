# 研究テーマ

[README](../README.md) / [文書一覧](README.md) / [既知の課題](KNOWN_ISSUES.md)

現在の研究はM5で終了しています。以下は候補の記録で、実装予定や着手承認ではありません。主力プロダクトを止める価値、検証する問い、終了条件を確認してから一つだけ選びます。投入時間・費用の上限は着手時に決め、未測定の改善率を目標にしません。

## 今回得られた成果

限定cgroupの観測・事前ルールによる拒否・解除・終了後の復帰を、Rust/Ayaと専用VMで確認しました。M5ではveil-rsの既存Rule APIを使い、値を返さない警告アダプタを検証しました。[段階別記録](../milestones/README.md)が証拠です。

これらは研究・OSSの成果です。収益、利用者需要、主力プロダクトへの導入価値は未検証で、本番保護への採用を意味しません。

## R1 プロセス識別と競合

- 問い：PID開始時刻とprocディレクトリFDで、どの再利用・終了・exec競合を検出できるか。
- 最小の検証：専用VM内の合成プロセスを終了・再生成し、読み取り時の状態を照合する。原子的スナップショットを前提にしない。
- 終了条件：値の非露出、未評価分類、子の終了・回収を各再現ケースで確認し、検出できない競合を明記したら区切る。安全条件が崩れたら適用範囲を拡大しない。
- 成果への接続：M5の誤評価を減らす根拠と回帰試験。一般的なDLPやプロダクトへの接続は未確認。

## R2 接続前の評価方法の比較

- 問い：明示ランチャー、アプリ側の送信前検査、プロキシなどの既存方法と比べ、どの境界なら評価完了後に送信を開始できるか。
- 最小の検証：一つの協調的な合成クライアントとloopback受信先で、検査前後の送信順序・エラー・迂回経路を比較する。実秘密やTLSの復号を使わない。
- 終了条件：評価対象・防げる経路・防げない経路を表にできた時点で終了。全ライブラリ・全子プロセスを保護する保証へ広げない。
- 成果への接続：veil-rsを送信前に使う場合の設計判断。主力プロダクトに同じ課題がある証拠がなければ導入しない。

## R3 エンジンの依存と資源予算

- 問い：同じ6ルールの意味を保ちながら、veil-coreの不要な機能を分離できるか。分離せず現状を固定する案も比較する。
- 最小の検証：現在の固定版を基準に、同じ合成入力で結果、依存、ビルド時間、ディスク、実行時メモリを比較する。ソース量や依存件数だけで性能改善と呼ばない。
- 終了条件：互換性、ライセンス、測定条件と差が説明できるかを確認し、採用・不採用を記録して区切る。上流変更や別プロジェクトへの編集は別の承認範囲とする。
- 成果への接続：M5のビルド容量と保守負担の判断材料。veil-rsへの還元可能性は比較結果が出てから評価する。

## R4 欠落時の利用者の判断

- 問い：TUIの「許可」「接続試行」「未評価」「欠落」の意味を、利用者が誤解せず判断できるか。
- 最小の検証：合成イベントと欠落を用いた少数の具体的タスクで、判断の正誤、所要時間、誤操作を確認する。外部参加者の募集や情報収集は自動で始めない。
- 終了条件：代表的な誤解と修正文言を特定し、必要な修正だけ検証して区切る。見た目の好みを測定結果として扱わない。
- 成果への接続：OSSの操作説明と警告表現。一般製品への適用価値は未確認。

## R5 限定サービスの運用と復帰

- 問い：固定cgroup・初期observeのまま、起動失敗・再起動・停止後の状態を明確にできるか。
- 最小の検証：[M6の保留仕様](../milestones/06-service/README.md)に従い、専用VMでserviceの起動・失敗・停止・再起動を確認する。
- 終了条件：再起動ループを抑え、管理SSHと対象外通信が維持され、停止後に保護がないことが分かる状態を確認したら区切る。
- 成果への接続：再現可能な研究デモの運用。常駐製品の需要・販売との接続がなければ追加投資しない。

## 今は始めないこと

全OS・全プロセス監視、TLSペイロードの復号、自動kill、検知からの自動拒否、本番DLP、Cloudflare連携は現在の目的に含めません。研究を追加しなくても、M0〜M5のデモ・文書・検証記録をOSSの成果として整理できます。
