# 監視・拒否・解除・復帰の短いデモ

専用NixOS VMで合成loopback通信だけを使います。M3の成果を5段階で確認するデモです。既存接続の停止や秘密の流出防止は扱いません。

## 実行

構築用VMと専用VMを起動してから、ホストのリポジトリで実行します。初回のVM準備は [実行ガイド](GUIDE.md) を参照してください。

```sh
nix develop "path:$PWD"
./scripts/build-counter-vm.sh
./scripts/demo-policy-vm.sh
```

デモは順に以下を実行し、JSONに実クライアントのerrnoと受信数を記録します。

| 段階 | 操作 | 期待するerrno | 受信メッセージ累計 |
| --- | --- | --- | --- |
| 1 | observeで送信 | 0 | 1 |
| 2 | enforceで宛先ルールを追加して送信 | EPERM（1） | 1 |
| 3 | ルールを解除して送信 | 0 | 2 |
| 4 | 同じルールを再追加して送信 | EPERM（1） | 2 |
| 5 | 監視プロセスを終了して送信 | 0 | 3 |

対象は `/warden.slice/warden-test.slice` です。クライアントは所属後にsocketを作り、各段階で新しいTCP接続を試みます。監視を終了してからenforceで起動し直し、準備完了後だけ通信します。最後に自作linkが残らず、管理SSHが維持されていることも確認します。

結果は `artifacts/m3a/demo-日時-PID.json` に残ります。失敗時は非ゼロ終了し、成功扱いにしません。VM・成果物・ディスクは自動削除しません。VMを使い終えたら [停止手順](GUIDE.md#停止と復帰) で停止します。

手動で操作したい場合は [M3の実行手順](GUIDE.md#m3-接続拒否と解除の実行) を使います。このデモはM3全体の受け入れ試験の代わりではありません。IPv6、対象外通信、容量超過、SIGKILL、ログ欠落の検証には `./scripts/test-policy-vm.sh` を使ってください。
