# M3A 完成整理

対象：M3の最終差分、文書と証拠の照合、短いデモ、コミット準備。機能の追加はM4として分ける。

## 確認

- M3は `e0debf0` にコミット済みで、着手時の作業ツリーはクリーンだった。
- M3A着手時の全ランタイムRustソースとCargo manifestは、M3実VM検証に使ったビルドarchiveの内容と一致した。
- M3 JSONの通常終了・SIGTERM・SIGKILL、拒否数4,096、RingBuf欠落3,841と文書の記述を照合した。
- kernelの判断はRingBuf予約前、ルールはtuple、observeが既定、FD linkはpinせず、プロセス情報はcommに限定されていることを差分で確認した。
- [5段階のデモ](../../docs/DEMO.md) と実行スクリプトを追加した。

## コミット準備

M3AはDEMO、デモスクリプト、connect_demo.py、この記録を中心にまとめる。M4のランタイム・依存・検証変更は別の差分として説明する。コミット・pushはこの作業では実行しない。

## 実測

5段階デモを専用Linux 6.18.54 VMで実行し、errnoは0 → 1 → 0 → 1 → 0、サーバー受信は1 → 1 → 2 → 2 → 3を確認した。リンク解除とSSH維持も通過。記録はartifacts/m3aに保持する。

M3A時点のscripts/check.shは通過した。M3Aの変更は新規デモ・文書で、既存のコミットを変更しない。M4の変更は別の機能として記録する。
