# 企業での限定試用に向けた段階案

[既存マイルストーン](../README.md) / [設計](../../docs/ENTERPRISE_READINESS.md) / [タスク](../../docs/ENTERPRISE_TASKS.md)

状態：設計候補。全段階未完了、M6は保留のまま。
文書整理の承認は実装・配布・本番運用の承認ではない。Keeper Cとは独立した計画。
最終ゴールは一つの実サービスへの安全な導入・運用・復旧。機能数やv1.0を達成指標にしない。

| 段階 | 利用者にとっての到達点 | 受け入れゲート | 状態 |
| --- | --- | --- | --- |
| W0 | 必要性と対象が明確 | 利用者/一サービス/一環境、代替比較、停止条件を合意。不要ならここで終了 | 未決定 |
| W1 = M6 | 非対話で観測・停止できる | 型付きJSON、readiness/欠落、既定observe、対象限定、停止解除を新規VMで実証 | 未着手・保留 |
| W2 | 本番でbuildせず限定試用できる | CLI+BPFの対応物、SBOM/帰属/署名検証、対応表、初回導入/停止/旧版復帰の実測。公開は別承認 | パッケージ・診断を先行実装、段階全体は未完了 |
| W3 | policyをレビューして管理できる | 一形式の設定、Auditとenforceの区別、世代更新と不正時旧版維持、実通信/復旧 | 未着手 |
| W4 | 必要な既存監視基盤へ接続できる | 要求がある場合だけ、意味が正しいmetricsと実collector受信/停止/欠落検出 | 条件付き・保留 |
| W5 | 必要な場合にK8s配置や保持更新へ進める | 単体試用実績、Pod寿命/共存/権限と、別の故障契約・独立復旧の実証 | 条件付き・保留 |

W0→W1→W2を先に評価し、W3は制御運用が必要な場合に進む。W4は要求によりW1後に選べる任意段階。
W5を初版の必須条件にはしない。日付・納期・資源予算は未決定で、着手時に必要十分な上限を別途決める。

現状のM0〜M5とArena固定VMの証拠は土台として参照するが、上表の完了チェックには転用しない。
各段階で管理経路喪失、対象外への影響、秘密出力、解除不能があれば中止する。
対象利用者の課題が既存手段で解決する場合、M5の研究成果を維持して追加実装を止める。
